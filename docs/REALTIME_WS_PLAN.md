# 实时行情 WebSocket 方案（先方案，后接入）

> 目标：在不破坏现有 HTTP 轮询的前提下，让顶部指数、自选报价、分时最新点可以“推”进来，减少 20 秒轮询的延迟感。
> 本文只给方案；当前版本仍使用 HTTP 轮询，默认不建立任何长连接。

## 1. 结论先说

**有可以试的公开 WebSocket 接口，而且已经实测可用：**

```
wss://hq.sinajs.cn/wskt?list=sh000001,sz399001,sz399006
```

- 协议：标准 WebSocket，文本帧。
- 鉴权：不需要 token / cookie；**需要带 `Origin: https://finance.sina.com.cn`**（部分客户端还要求正常 UA）。
- 行为：连接后先回一条全量快照，然后**按股票逐条推送约每 3 秒一次**的报价；单只股票一条消息。
- 数据格式：与新浪 HTTP 行情 `hq.sinajs.cn/list=` 相同的一行 `symbol=字段,字段,...`；A 股个股包含名称、开、昨收、现价、高、低、买一/卖一、成交量、成交额、五档盘口、日期、时间。
- 实测（2026-11-17 13:50，上证 / 深证 / 创业板 / 广百股份）：25 秒收到 31 条消息，每个 symbol 约 3 秒一条；指数与个股都正常。

它属于**新浪网页端的内部接口，不是正式开放 API**：没有 SLA、没有文档、可能限流或变更，不能作为唯一数据源。

### “节点数据”要说清楚

这条推送是 **3 秒级快照**，不是逐笔成交（tick），也不是 Level-2 十档/委托队列。

- 对于「指数分时、自选涨跌、最新价闪烁、分时图最后一个点」：完全够用。
- 对于「逐笔成交、大单、封单变化、千档盘口」：需要付费数据源（见第 5 节）。

## 2. 候选接口对比

| 来源 | 接口 | 实测 | 评价 |
| --- | --- | --- | --- |
| 新浪 | `wss://hq.sinajs.cn/wskt?list=...` | ✅ 可连、约 3 秒推送 | **首选试验对象**；无需鉴权，但非官方 |
| 腾讯 | `wss://web.sqt.gtimg.cn/ws/` | ❌ 握手返回 200 而非 101 | 可能要求特定子协议/路径，暂不投入 |
| 腾讯 | `wss://ws.gtimg.com/app/ws` | ❌ TLS 流被关闭 | 可能只对 App 端开放 |
| 东方财富 | `wss://push2.eastmoney.com/ws` | ❌ HTTP 404 | 东财 Web 端主要是 HTTP 短轮询，不是公开 WS |
| 雪球 | `wss://stock.xueqiu.com/socket.io/...` | ❌ 403 | Socket.IO，需要登录 Cookie，不建议 |
| 同花顺 | 未找到公开 WS | — | 现有涨停池仍是 HTTP 接口 |
| 商业数据 | AllTick / 聚宽 / 万得 / 同花顺 iFinD | 需账号 | 真·逐笔/L2 只能走商业授权 |

## 3. 推荐架构（Rust 侧持有长连接）

```
┌──────────────┐    wss     ┌──────────────────────────┐   Tauri event   ┌───────────────┐
│ 新浪 wskt    │ ─────────▶ │ Rust realtime session    │ ──────────────▶ │ 前端事件总线  │
└──────────────┘            │  - 订阅集合 / 分片        │  quote:tick     │ 顶部指数      │
                            │  - 去重 / 节流 / 重连     │  quote:status   │ 自选 / 天梯   │
┌──────────────┐   HTTP     │  - 交易时段 / 降级        │                 │ 分时最新点    │
│ 现有轮询源   │ ─────────▶ │  - 快照 + 增量             │                 │               │
└──────────────┘            └──────────────────────────┘                 └───────────────┘
```

### 3.1 连接与订阅

- 用 `tokio-tungstenite`（或 `tokio::net::TcpStream` + `tungstenite`）在 Rust 侧建连；带 `Origin` 与 UA。
- 订阅集合 = 3 个指数 + 当前涨停池（约 40–60 只）+ 自选（最多 80 只）+ 当前打开的个股。去重后按 **每连接 ≤ 40 只** 分片，最多 3 条连接。
- 连接 URL 的 `list=` 参数在握手时确定；变更新订阅时：
  - 若新增很少：直接重连（简单可靠）；
  - 若频繁变化：维护“订阅代际”，旧连接延迟 2 秒关闭，避免抖动。
- 只在交易时段（09:15–11:35、12:55–15:05）保持连接；盘后主动断开，避免无意义常驻。
- 窗口隐藏 / 最小化时暂停事件到前端的推送（Rust 侧仍可维护最近快照），恢复时补一份全量。

### 3.2 解析与数据契约

新增（复用现有 `StockQuote` 字段，避免前端大改）：

```rust
pub struct QuoteTick {
    pub code: String,       // sh000001 / sz002187
    pub name: String,
    pub price: f64,
    pub prev_close: f64,
    pub open: f64,
    pub high: f64,
    pub low: f64,
    pub volume: f64,
    pub amount: f64,
    pub bids: Vec<(f64, f64)>, // 五档，可选
    pub asks: Vec<(f64, f64)>,
    pub as_of: String,       // 交易所时间
    pub received_at: i64,    // 本地接收时间（秒）
    pub source: String,      // "sina-ws"
}
```

- 前端事件：`quote:tick`（单只/批量均可）、`quote:status`（`connecting | live | reconnecting | offline | fallback`）。
- 节流：Rust 侧按 `code` 保留最新一条，前端每 **200–500ms** 批量刷新一次 DOM；不要每条消息都触发整页 render。
- 去重：同一 `as_of` + 同一价格不重复发；停牌/集合竞价状态要保留。
- 交易时段外收到的时间戳要校验，避免把昨天的收盘快照当今天。

### 3.3 前端接入点（按收益排序）

1. **顶部指数**：替代 20 秒一次的 `get_indices`；指数 mini 分时追加当前点（现有 `IndexQuote.spark` 末尾追加，最多保留 240 点）。
2. **自选 / 天梯卡片涨跌**：只更新文字与颜色，不重排 DOM。
3. **分时图最新点**：把 `TimeShareChart` 的最后一个点扩展到“当前时刻”；已有红点闪烁，接上推送后红点会真正每 3 秒移动。
4. **盘口池价格**：涨停池/炸板池的现价与封单变化；注意不要触发整页进入动画，复用 `renderMain` 之外的局部更新函数。
5. **涨停池列表**：新增/掉出涨停池需要 HTTP 重新拉取（WS 只推动报价，不推动池子成员变化），保留现有 60 秒池子刷新。

### 3.4 可靠性

- 心跳：每 20–25 秒发 WebSocket Ping；30 秒无消息判定假死并重连。
- 重连：指数退避 1s → 2s → 4s → 8s → 15s，带 ±20% 抖动；连续失败 5 次后降级 HTTP 轮询并提示“实时推送暂不可用，已回退轮询”。
- 启动/切日/休市：主动关闭并清理订阅，避免跨日把旧数据推给新页面。
- 监控：在设置页显示“实时通道：已连接 / 重连中 / 回退轮询”，并提供开关（默认先关闭，标注“实验性”）。
- 失败隔离：WS 失败绝不影响现有 HTTP 数据；所有 UI 都能在纯轮询下工作。

### 3.5 法规与稳定性

- 这些接口是网页端公开接口，适合个人学习复盘；不要高频重连、不要多开连接刷接口。
- 不把 WS 数据写入对外服务、不做二次分发。
- 正式产品化建议换有授权的数据源（见下）。

## 4. 分阶段落地

**阶段 1（0.5 天，试验）**
- 加一个独立的 `scripts/probe-sina-ws.ps1`（本仓库已附）：输入代码列表，打印 20 秒推送，确认本机网络可用。
- 不接主流程。

**阶段 2（1–2 天，指数 + 自选）**
- Rust 增加 `realtime` 模块与 `start_realtime/stop_realtime` 命令。
- 只订阅 3 个指数 + 自选，前端通过 Tauri event 更新顶部与自选；设置页加开关。
- 保留 60 秒 HTTP 兜底。

**阶段 3（1–2 天，分时/天梯）**
- 分时图追加实时点；天梯卡片局部更新。
- 涨停池成员仍走 HTTP，报价走 WS。
- 加入状态指示与回退提示。

**阶段 4（可选）**
- 评估商业逐笔/L2（AllTick、聚宽、万得、同花顺 iFinD），替换 `source` 层，不动 UI。

## 5. 如果要做“真·逐笔 / L2”

需要商业授权或券商接口：

- **AllTick**：有 A 股实时 tick / 盘口 API，按订阅收费，接入简单。
- **聚宽 / 米筐**：研究平台，实时性按套餐。
- **万得 Wind / 同花顺 iFinD**：机构级，成本高。
- **券商交易接口**：需要开户和柜台权限，适合交易端，不适合纯复盘工具。

对本项目而言，3 秒快照 + 现有 1 分钟分时已经足够支撑“看高度、看主线、看盘口”的定位；不建议为逐笔数据引入高成本依赖。

## 6. 试一下

仓库附带脚本（PowerShell 5.1+，Windows 自带）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/probe-sina-ws.ps1
# 自定义代码与时长
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/probe-sina-ws.ps1 -Codes "sh000001,sz002187" -Seconds 30
```

脚本只建立一条只读连接，不写文件、不改应用数据；20 秒后自动关闭。
